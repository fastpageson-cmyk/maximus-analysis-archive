# 점포(가게) 단위 의외성 추천: 선택지와 추천안

작성: 2026-11-02 · 브랜치 `codex/gunwoo/store-level-recommendation-options`(`codex/gunwoo/serendipity-ranking`에서 분기)
범위: 조사와 설계만 했다. 코드는 바꾸지 않았다. 숫자는 저장소 안 가공 파일로 바로 셀 수 있는 것만 넣었다(0.3절).

> **왜 필요한가.** SERP-v0(`docs/serendipity_recommendation_design.md`)는 공식 상권 786곳 단위로 추천한다. 그런데 상권 폴리곤이 넓다. 골목상권 중앙값은 7.9만㎡(대각선 605m), 발달상권은 14.8만㎡(879m), 관광특구는 62.6만㎡(1.7km, 최대 4.1km)다. 그래서 "이태원 관광특구가 의외의 장소"라는 말만으로는 실제로 어느 가게로 가야 할지 알 수 없다.

## 0. 추천안 (먼저 읽을 것)

### 0.1 추천: **2단계 결합(안 B)**. 상권 R×U로 상권을 고르고, 그 상권 안 점포를 공공데이터 규칙 점수로 다시 매긴다

```
1단계  SERP-v0 그대로: 목적별 R ≥ 0.6 상권 → S_area = R × U → MMR 상위 10곳
2단계  고른 상권 안 점포마다
         gate      : 목적 업종 일치 ∧ 영업 중 ∧ 비프랜차이즈 ∧ 점포까지 도착 ≤ 30분(도보 보정)
         r_store   : 영업 지속기간 백분위(0.6) + 착한가격·오래가게 지정(0.4)        ← 관련성(품질 대리)
         u_store   : 상권 안 소분류 희소도(0.4) + 노포/10년+(0.3) + 관성 업종과의 거리(0.3) ← 새로움·의외성
         s_store   = r_store × u_store
       상권마다 점포 3곳(MMR, 같은 소분류 1곳까지) → 카드 = "상권 이름 + 이 가게 3곳 + 이유"
최종   S = S_area × s_store 로 30곳을 다시 섞음(상권당 최대 3곳)
```

**이유**
1. **이미 있는 것을 그대로 쓴다.** 상권 단위 R·U·MMR·관성 기준선·백테스트(SERP-v0)는 그대로 둔다. 점포 단계는 글캠 `build_mohyeon_hidden_stores_v0.py`·`build_mohyeon_recommendations_v1.py`의 인허가↔상가 매칭, 프랜차이즈 판정, 노포·10년+·착한가격·희소 업종 태그를 서울로 옮기기만 하면 된다. 서울캠 `build_seoulcampus_area_tags_v1.py`가 서울 인허가 16만 건을 이미 읽고 있다.
2. **점포 단위 신호는 '매력'보다 '새로움'에 강하다.** 점포별 매출·방문·평점 같은 공개 데이터는 없다(1.3절). 그래서 관련성 R은 상권 단위 매출·유입 모형(Ridge)에서 가져오고, 점포 단계는 공공데이터로 잴 수 있는 새로움·의외성 위주로 매긴다. 이렇게 나누면 신호가 없는 쪽을 억지로 만들지 않아도 된다.
3. **후보 수가 맞다.** SERP-v0 목적별 상위 10곳(중복 빼면 36곳) 안의 태그 점포(노포+10년+·오래된 카페+착한가격)는 상권당 중앙값 20곳, 합계 1,539곳이다. 36곳 중 34곳은 3곳 이상이라 상권마다 3곳을 고를 수 있다(0.3절).
4. **교수님 피드백 범위 안이다.** 규칙 점수와 백분위만 쓴다. 설문 라벨이 모이면 같은 변수로 조건부 로짓을 추정해 가중치를 바꾼다(3.4절).

### 0.3 저장소 안 데이터로 해 본 실현 가능성 확인

`seoulcampus_area_tags_v1.csv`(786곳)와 SERP-v0 결과로 셌다. 태그 개수는 비프랜차이즈·영업 중 인허가 기준이다.

| 확인 | 결과 |
|---|---|
| 상권당 태그 점포 수(노포+10년+·오래된 카페+착한가격) | 중앙값 13, 평균 28.7, 최대 852(종로·청계) |
| 태그 점포가 0곳인 상권 / 3곳 미만 | 36곳 / 101곳(786 중 13%) |
| 10곳 이상 / 50곳 이상 | 476곳 / 102곳 |
| 태그 수와 상권 총 점포 수의 상관 | 0.75. 개수 그대로 쓰면 큰 상권이 이긴다(limitations #8) |
| 태그 수 ÷ 식사+카페 점포 수 | 중앙값 0.088(식사·카페 11곳 중 1곳 꼴) |
| SERP-v0 목적별 상위 10(중복 제외 36곳)의 태그 점포 | 상권당 중앙값 20, 합계 1,539. 3곳 미만은 2곳(공부 목적 골목상권), 30곳 이상 12곳 |
| 같은 36곳의 폴리곤 대각선(경계 상자) | 중앙값 564m, 800m 넘는 곳 6곳, 1.5km 넘는 곳 2곳(이태원 관광특구 1.6km, 이태원역 1.5km) |
| 걸어서 상권 중심→가장자리(대각선 절반, 시속 4km) | 중앙값 약 4분, 이태원 관광특구 약 12분 |
| 글캠 추천 v1 점포 3,243곳의 태그 수 | 태그 1개 91%(2,983), 2개 8%(255), 3개 5곳. **태그 개수로 정렬하면 거의 구별이 안 된다** → 점수가 필요한 근거 |

서울 점포 **목록**은 저장소에 없다. 태그 파일에는 개수와 대표 상호 3개만 있고, 원천(인허가·SBIZ)은 커밋 금지라 이 세션에서는 실제 점포 순위를 만들 수 없다.

### 0.4 막히는 지점

1. **원천이 이 세션에 없다.** 서울 인허가 3종·SBIZ·착한가격은 `<작업 폴더>/데이터/원천/서울캠/`(건우 로컬)에만 있다. 1·3·4번 작업은 로컬에서 돌려야 한다. 이 세션에서는 `www.data.go.kr`·`data.seoul.go.kr`이 네트워크 정책으로 막혀서 메타데이터 페이지도 직접 열지 못했다. 2장 표의 '확인 필요' 칸은 이 때문이다.
2. **착한가격 좌표가 카카오 응답이다.** 서울캠 태그의 착한가격 2,208곳 좌표는 카카오 주소검색 결과다. 카카오 개발자 포럼 답변 기준으로는 좌표·이름·주소를 저장해 다시 쓰는 것이 허용되지 않는다(5장). 점포 단위로 화면에 내려면 공공 지오코더로 바꿔야 한다.
3. **30분 판정이 점포 단위로 내려가지 않는다.** 동대문구 PATH-v0는 상권 단위 도달률이고, 서울캠은 274곳 중 214곳(78%)이 직선 추정이다. 측정된 60곳 중 28곳은 25~30분 경계다. 점포별로 ODsay를 부르기에는 한도(하루 약 30건)가 너무 작다(4.3절).
4. **점포 단위 정답 라벨이 없다.** 점포별 매출·방문·평점 공개 데이터가 없고 리뷰 수집은 금지다. 관련성(맛·만족)은 설문으로만 확인할 수 있다.
5. **노포 판정 오류.** 인허가일자는 지위승계 뒤에도 남는다(글캠 '위드치킨 1989'). 매칭 정밀도도 아직 측정하지 않았다(limitations #6).

### 1.2 요약
- **글캠에는 이미 점포 단위 추천이 있다.** 다만 점수 없이 태그 개수와 도착 시간으로만 정렬하고, 91%가 태그 1개라 순위가 사실상 없다.
- **서울캠은 점포를 세기만 하고 목록은 내지 않는다.** 서울 점포 목록을 만드는 데 필요한 코드 조각(정규화·프랜차이즈·매칭·공간결합)은 이미 다 있다.
- **동대문구 SERP-v0(상권)와 서울캠 태그(상권)는 `area_code` 하나로 바로 붙는다.** 2단계 결합의 연결고리다.

## 3. 점포 단위 의외성 점수: 세 가지 안

### 3.1 개인 평점 없이 가능한 신호와 불가능한 신호

|---|---|---|

### 3.2 안 A: 점포 규칙 점수만(상권 무시)
- 30분 안 모든 점포(서울 기준 수만 곳) 중 목적 업종·영업 중·비프랜차이즈만 남긴다.
- 관련성 `r = 백분위(영업기간)·0.7 + 착한가격·0.3`, 새로움 `n = 희소도·0.5 + 노포·0.5`, 의외성은 관성 상권 Top-K까지 거리로 둔다. `S = r × (n + u)/2`로 정렬한다.
- 장점은 단순하다는 것이다. 단점이 크다. 상권 단위 매출·유입 모형(R)을 버리게 되고, 후보가 수만 곳이라 30분 판정을 점포마다 해야 한다. 결과도 노포 많은 종로·청계에 몰린다(태그 수와 점포 수 상관 0.75).

### 3.3 안 B: 2단계 결합(**추천**, 0.1절)
- 1단계: SERP-v0의 `S_area = R × U`, R ≥ 0.6 하한, MMR 상위 K(=10) 상권.
- 2단계 점포 점수 정의:
  - **gate**: 목적 업종 일치 ∧ 영업 중(인허가 `SALS_STTS_CD=01`) ∧ 비프랜차이즈 ∧ `t_store ≤ 30`(4.3절).
  - `r_store = 0.6·pct(영업연수 | 같은 소분류) + 0.4·max(착한가격, 오래가게)`. 같은 소분류 안 백분위로 바꿔, 카페가 한식보다 늘 젊게 나오는 문제를 없앤다.
  - `u_store = 0.4·희소도 + 0.3·노포(2005 이전)/10년+(2006~2015, 0.5점) + 0.3·관성업종거리`
    - 희소도 = `1 − pct(같은 상권 안 같은 소분류 점포 수)`. 글캠 `rare_type`(2곳 이하)을 연속값으로 바꾼 것
    - 관성업종거리 = 그 점포 소분류가 관성 Top-K 상권들의 업종 구성에서 차지하는 비중의 역백분위. SERP-v0 `u_cat`을 점포로 내린 것
  - `s_store = r_store × u_store`. 상권 안에서 MMR로 3곳(같은 소분류는 1곳).
  - 최종 `S = S_area × s_store`, 상권당 최대 3곳, 목적별 30곳.
- 장점: 상권 R의 근거(매출·유입 Ridge)를 유지한다. 후보가 1,500곳 안팎이라 매칭 검수와 도보 보정을 할 수 있는 규모다. 카드에 "왜 이 상권 + 왜 이 가게"를 둘 다 적을 수 있다.
- 단점: 1단계에서 떨어진 상권 안의 좋은 가게는 못 나온다. 이를 보완하려면 R ≥ 0.6 상권 전체(목적별 315곳)를 2단계 후보로 열고 K를 민감도로 본다.

### 3.4 안 C: 안 B + 라벨이 생기면 조건부 로짓
- 안 B의 변수(r·u 성분, 도착 시간, 상권 S)를 설명변수로 두고, 설문 '가고 싶다' 선택(카드 묶음에서 1곳 고르기)을 **조건부 로짓**으로 추정해 가중치를 데이터로 정한다. 교수님 피드백의 주모형과 맞는다.
- 표본이 모이면(예: 30명 × 묶음 10개 = 300 선택) LightGBM/CatBoost 순위 모형과 비교한다. 그 전까지는 고정 가중치(안 B)를 쓴다.
- 라벨 없이 지금 할 수 있는 일은 안 B까지다. 안 C는 4장의 설문 뒤에 한다.

## 4. 라벨 문제, 검증, 30분 판정

### 4.1 라벨 문제
- 점포 단위 '좋은 의외의 곳' 정답이 없다. SERP-v0는 상권 단위라 다음 분기 매출·유입 증가를 사후 프록시 라벨로 썼지만, 점포 단위에는 그런 공개 지표가 없다.
- 쓸 수 있는 약한 프록시는 **생존**(다음 분기·다음 해에도 영업 중)뿐이다. 이는 관련성의 하한(망하지 않을 곳) 정도만 보여 주고 의외성과는 상관이 없다. 인허가 폐업일자로 백테스트를 할 수 있다. 예: 2024년 말 기준 점수로 2025년 말 생존율을 상위 10%와 무작위 사이에서 비교한다.
- 노포 판정 자체의 정확도는 따로 잰다(표본 50곳 수동 확인: 상호 일치, 지위승계 여부). limitations #6이 아직 남아 있다.

### 4.2 설문(3문항, 카드 단위)
카드 = 가게 이름·업종·상권·도착 시간·이유 한 줄. 학생 20~30명, 1인당 카드 20장(의외성 10 + 기준선 10, 순서 무작위, 출처 숨김).

| 문항 | 측정 | 척도 |
|---|---|---|
| Q1. 이 가게를 알거나 가 본 적이 있나요? | 새로움 | 가 봄 / 들어 봄 / 처음 |
| Q2. 내가 평소 갈 곳으로 떠올렸을 것 같나요? | 의외성 | 1~5(역) |
| Q3. 30분 안이라면 가 보고 싶나요? | 관련성 | 1~5 |

- **세렌디피티 적중** = Q1 '처음' ∧ Q2 ≤ 2 ∧ Q3 ≥ 4. Kotkov식 곱 정의를 이진화한 것이다.
- 기준선(점포 단위 관성): ① 같은 상권 안 상권 중심에서 가까운 순, ② 같은 상권 안 무작위 비프랜차이즈, ③ 관성 상권(SERP-v0 관성 Top-K)의 같은 규칙 상위 점포.
- 비교 지표: 적중률, Q3 평균(관련성이 무너지지 않았는지), Q1 '가 봄' 비율. 응답자 무작위효과를 둔 로짓으로 방법 효과를 보고, 같은 자료로 안 C를 추정한다.
- 한계: 한국외대 학생 표본이라 동대문구 일반 이용자로 일반화하기 어렵다. 1인 20장이면 피로도가 있으니 10장 2회로 나눌 수 있다.

### 4.3 30분 판정: 상권 대표점과 점포 좌표
- 지금은 상권 대표점(또는 동대문구 출발지 334곳의 30분 도달률)으로 판정한다. 점포는 상권 안 어디에나 있을 수 있다. SERP-v0 상위 36곳의 대각선 중앙값은 564m(도보 약 4분), 이태원 관광특구는 1.6km(가장자리까지 약 12분)다.
- **추천 보정식:** `t_store = t_area − walk(도착 정류장/역 → 상권 대표점) + walk(도착 정류장/역 → 점포)`. walk는 직선 × 1.3 ÷ 시속 4km(글캠 모형은 1.25를 썼는데 산지에서 낙관적이었다. 서울 평지는 1.3으로 둔다).
  - ODsay 측정 상권은 응답에 마지막 하차 지점이 있으므로 그 좌표를 쓴다. 미측정(직선 추정) 상권은 상권 안·근처 역·정류장 중 가장 가까운 곳을 하차점으로 본다.
  - 저장소의 `scripts/build_seoul_transit_network.py`(서울 정적 노선망)로 정류장→점포 도보 구간을 붙이면 API 호출 없이 계산할 수 있다.
- **표시 규칙:** `t_store ≤ 25` 안정, 25~30 `경계`(서울캠 측정분 60곳 중 28곳이 이미 이 구간), 30 초과는 제외. 대기시간(`wait_risk`)은 그대로 넘겨 받는다.
- 점포마다 ODsay를 부르는 방식은 하루 약 30건 한도 때문에 할 수 없다(1,500곳 = 50일).

| TourAPI | 텍스트는 자유 이용 정보만 제공한다고 안내하지만, 이미지는 공공누리 1·3유형(3유형은 변경 금지)이 섞여 있다 | 이미지는 쓰지 않고 '관광공사 소개 여부' 플래그만 쓴다 |
| 대회 규정·리뷰 | 약관을 어기는 리뷰 크롤링은 심사 제외 | 평점·리뷰·SNS 언급은 쓰지 않는다(3.1절 '불가능'). 관련성은 설문으로만 확인한다 |
| 원천 커밋 | 공개 저장소 | 원천·API 캐시·키는 지금처럼 `<작업 폴더>/데이터/`에만 둔다. 공개 결과에는 상호·업종·상권·태그·도착 시간까지만 남기고, 좌표는 상가정보·인허가 유래만 쓴다 |
